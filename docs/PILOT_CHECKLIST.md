# Supervised pilot commissioning pack

**BLOCKED: no authorised hardware/site.** Zero physical sites are approved. The
software/simulator branch is implemented so preparation can proceed without
inventing supplier capability, customer consent or professional sign-off.

For each of the two intended pilot sites, a qualified human must record and review:

- Customer/site access agreement, controller/processor terms, support boundaries,
  responsible QA/operations contacts and approved read-only network scope.
- Partner profile/version and verified capabilities: units/range, probe identity,
  calibration traceability/expiry, source-clock accuracy, sampling cadence, sequence
  reset and actual buffering/network-discontinuity behavior.
- Installation/placement references, reference instrument/readings, calibration
  records and technician identity. Software fixtures cannot substitute for these.
- Customer QA/HACCP limits, duration/hysteresis, cadence/grace, SOP reference and
  test/backtest review; no universal legal or safe temperatures are supplied.
- Controlled breach/recovery, silent probe/gateway outage, delayed/backfilled data,
  reboot/replay, route/shift/contingency and human acknowledgement drills. Provider
  acceptance remains distinct from a responsible person's response.
- Commissioning acceptance archive, training attendance/roles, independent
  monitoring/contingency procedure and explicit customer go-live authorization.
- Sprint 10 image remediation, external security/privacy/legal/licence review,
  hardened deployment/PKI, cloud paging, backup custody/PITR and restore reconciliation.

Use Inventory's placement/calibration/site-pack/test/QA acceptance workflow to retain
the **synthetic** preparation evidence. Its current activation endpoint remains
blocked. An implementation supporting actual authorized deployment must be reviewed
separately; setting a boolean or entering a document reference cannot bypass it.

Daily software review: check source and receipt freshness, watcher/queue/rule lag,
calibration currency, unresolved incidents, notification failures, stalled reports
and backup age; record responsible follow-up without clearing source evidence.
Weekly feedback: record false/missed/no-data episodes, acknowledgement/response
times, operator usability, support effort, retention/storage growth and agreed
changes. Append new observations instead of rewriting the original review.

Current software review archive lives under exact-site `pilot-reviews/`; all rows
and snapshots remain explicitly synthetic. Real daily reviews and customer feedback
are **NOT RUN**, pending agreements, qualified installation and supervised access.
